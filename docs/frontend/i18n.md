# Mehrsprachigkeit (i18n)

Vereint übersetzt zur Laufzeit: Je Sprache gibt es **eine JSON-Datei**, gewechselt
wird ohne Neuladen und ohne eigenen Build je Sprache. Deutsch ist Standard- und
Rückfallsprache, Englisch ist mitgeliefert.

## Neue Sprache hinzufügen (Checkliste)

Beispiel: Französisch (`fr`).

1. **App-Texte**: `webservice/src/app/i18n/locales/de.json` nach `fr.json`
   kopieren und alle Werte übersetzen. Schlüssel und `{platzhalter}` bleiben
   unverändert.
2. **Sprache registrieren**: in `webservice/src/app/i18n/languages.ts` einen
   Eintrag ergänzen:
   ```ts
   { code: 'fr', label: 'Français', locale: 'fr-FR', load: () => import('./locales/fr.json') },
   ```
   Damit erscheint die Sprache in der Sprachwahl im Profil, wird aus der
   Browsersprache erkannt und an API und Keycloak weitergegeben.
3. **Fehlertexte des Fachservice**: `baseservice/src/main/resources/i18n/messages_en.properties`
   nach `messages_fr.properties` kopieren, übersetzen und `fr` in
   `vereint.i18n.supported-locales` (`baseservice/src/main/resources/application.yaml`)
   ergänzen. Details: [Fachservice-i18n](../baseservice/i18n.md).
4. **Anmeldeseiten (Keycloak)**: `keycloak/themes/vereint/login/messages/messages_en.properties`
   nach `messages_fr.properties` kopieren und übersetzen, `fr` in `locales=` von
   `keycloak/themes/vereint/login/theme.properties` und in `supportedLocales` von
   `keycloak/realm-export.json` und `keycloak/dev/realm-export-dev.json` ergänzen.
   Alle übrigen Keycloak-Texte bringt Keycloak selbst in vielen Sprachen mit.
   Bestehende Realms übernehmen `supportedLocales` nicht automatisch aus dem
   Export: dort einmalig unter *Realm settings → Localization* nachtragen.
5. `npm test` im `webservice/`: Ein Test prüft, dass `en.json` dieselben
   Schlüssel und Platzhalter wie `de.json` hat. Für weitere Sprachen ist das
   nicht Pflicht: Fehlt ein Schlüssel, erscheint der deutsche Text. Wer
   Vollständigkeit erzwingen will, ergänzt die Sprache in diesem Test
   (`webservice/src/app/i18n/i18n.service.spec.ts`).

## Wie die Sprache bestimmt wird

1. Cookie `vereint.lang` – gesetzt, sobald jemand im Profil eine Sprache wählt
   (ein Jahr gültig, nicht HttpOnly, kein Geheimnis).
2. Sonst die Browsersprache (`navigator.languages`, beim SSR `Accept-Language`).
3. Sonst Deutsch.

Dieselbe Sprache gilt durchgängig:

| Ebene | Mechanismus |
| --- | --- |
| Angular-App (Browser und SSR) | `I18nService` lädt das Wörterbuch vor dem ersten Rendern (App-Initializer), setzt `<html lang>` |
| Fachservice-API | Interceptor schickt `Accept-Language: <sprache>` an `/api/…`; der BFF reicht den Header durch, Spring liefert Fehlertexte (`detail`) in dieser Sprache |
| Keycloak-Anmeldung | Der BFF hängt beim Login `ui_locales=<sprache>` an die Autorisierungs-URL |

Deutsch ist fest im Bundle, damit Texte sofort und auch in Tests ohne Laden
verfügbar sind; alle anderen Sprachen werden erst bei Bedarf als eigener Chunk
geladen.

## Texte im Code verwenden

Schlüssel sind nach Bereich gegliedert (`chat.composer.placeholder`). Neue Texte
kommen immer in **beide** Dateien `de.json` und `en.json`.

Templates – `TranslatePipe` aus `src/app/i18n` in die `imports` der Komponente:

```html
<h1>{{ 'wallet.title' | t }}</h1>
<button [attr.aria-label]="'common.close' | t">…</button>
<p>{{ 'wallet.balanceOf' | t: { name: member.displayName } }}</p>
<span>{{ 'events.participants' | t: { count: n } }}</span>
```

TypeScript (Signals, Services, Formatierungshelfer):

```ts
import { activeLocale, translate } from '../i18n/i18n.service';

this.error.set(translate('catalog.errors.save'));
new Intl.DateTimeFormat(activeLocale(), { dateStyle: 'medium' }).format(date);
```

`translate()` erst beim Bedarf aufrufen (nicht in Konstanten auf Modulebene),
damit ein Sprachwechsel greift. Datums-, Zahlen- und Währungsformate laufen
über `activeLocale()` statt fest `de-DE`.

### Platzhalter und Plural

```json
{
  "greeting": "Hallo {name}",
  "participants": { "zero": "Noch keine Teilnehmer", "one": "1 Teilnehmer", "other": "{count} Teilnehmer" }
}
```

Bei Objekten mit `one`/`other` (optional `zero`, `two`, `few`, `many`) wählt
`Intl.PluralRules` der jeweiligen Sprache die Form anhand von `count`.

Nicht übersetzt werden Inhalte der Mitglieder (Chat, Eventtitel …), API-Werte,
Logmeldungen und Code-Kommentare.
